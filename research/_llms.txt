# v5 Spot Router API

- **OpenAPI Version:** `3.1.0`
- **API Version:** `0.1.0`

Meta-router for gasless spot swaps. It fans out to the liquidity venues enabled on this chain (`robinhood-mainnet`, chain id 4663), returns the best executable route, and relays taker-signed settlements on-chain with relayer-paid gas.

## Swap flow

1. `GET /v1/tokens` / `GET /v1/deployment` — discover tradable tokens and contract addresses.
2. `GET /v1/price` — indicative multi-venue price for rate display (optional).
3. `GET /v1/quote` — firm quotes; pick one (usually `recommended`) and have the taker sign its `toSign` EIP-712 payload.
4. `POST /v1/submit` — submit the signed payload; the router broadcasts settlement and returns a `txHash`.
5. `GET /v1/status` — poll the transaction until `confirmed` (or `failed`, e.g. `SLIPPAGE_EXCEEDED`).

`POST /v1/deposit` separately relays gasless spot → perp deposits.

## Machine-readable access

- OpenAPI document: [/openapi.json](/openapi.json)
- Markdown for LLMs: [/llms.txt](/llms.txt)
- MCP server (Streamable HTTP): `/mcp` — every documented operation is exposed as a tool, so AI agents can explore prices, quotes, and deployments directly.

### Health and deployment summary

- **Method:** `GET`
- **Path:** `/health`
- **Tags:** Meta

Liveness probe reporting the configured chain, enabled venues, and SwapShell.

#### Responses

##### Status: 200 Service is up

###### Content-Type: application/json

- **`chainId` (required)**

  `integer` — Chain this router instance serves

- **`ok` (required)**

  `boolean`

- **`swapShell` (required)**

  `object` — SwapShell settlement contract, if configured

- **`venues` (required)**

  `array` — Venues enabled on this chain

  **Items:**

  `string`, possible values: `"zerox", "bebop", "arcus", "rialto", "lifi"` — Liquidity venue. The set enabled for this deployment is reported by GET /health.

**Example:**

```json
{
  "ok": true,
  "chainId": 4663,
  "venues": [
    "zerox"
  ],
  "swapShell": "0xf64780eAE9CFe162EF38f5224459a014a1007cd5"
}
```

### Indicative multi-venue price

- **Method:** `GET`
- **Path:** `/v1/price`
- **Tags:** Pricing

Fans out to enabled venues that list both the sell and buy token addresses and returns indicative prices for rate display, plus the router's `recommended` venue and `details` (RFQ makers, Uniswap pools, …). No commitment — use GET /v1/quote for an executable quote.

#### Parameters

##### `chainId`

- **In:** `query`

Optional sanity check; must match the router chain (see GET /health) when present

`integer`

##### `sellToken` required

- **In:** `query`

Token being sold

`string`

##### `buyToken` required

- **In:** `query`

Token being bought (use 0xEeee…EEeE for native ETH where supported)

`string`

##### `sellAmount` required

- **In:** `query`

Positive sell amount in base units (base-10 string)

`string`

##### `allowWrapped`

- **In:** `query`

Opt in to wrapped (synthetic) settlement of the buy token; must match the signed intent. Default false.

`string`, possible values: `"true", "false"`

##### `smartWallet`

- **In:** `query`

Taker's delegated EIP-7702 smart-wallet implementation address; venues that can't verify its signatures are skipped

`string`

##### `sourceInclude`

- **In:** `query`

Comma-separated venues eligible to win `recommended`

`string`

##### `sourceExclude`

- **In:** `query`

Comma-separated venues excluded from winning `recommended`

`string`

##### `builderFeeBps`

- **In:** `query`

Per-request builder fee in human bps. Requires X-Api-Key. Must be ≤ the key's max builderFeeBps; omitted or 0 collects none. Paid to the key's builderFeeRecipient. Repeat the same value on /v1/submit. Combined with protocol bps, also capped by ARCUS\_MAX\_TOTAL\_FEE\_BPS.

`number`

          `string` — Kebab-case protocol, e.g. rfq, uniswap-v3, uniswap-v4, circus, 1inch

          `integer` — Uniswap pool fee tier, e.g. 500 for 0.05%

          `string` — Hop input token

          `string` — RFQ maker id when protocol is rfq

          `string` — V2/V3 pool address, or V4 PoolId

### Firm multi-venue quote

- **Method:** `GET`
- **Path:** `/v1/quote`
- **Tags:** Pricing

Returns firm, signable quotes from enabled venues that list both the sell and buy token addresses. Pick one (usually `recommended`), have the taker sign its `toSign` EIP-712 payload, then POST /v1/submit. Each quote carries `details` for the liquidity legs. Arcus native-ETH BUY quotes return a ready-to-broadcast `transaction` instead of `toSign`.

#### Parameters

##### `chainId`

- **In:** `query`

Optional sanity check; must match the router chain (see GET /health) when present

`integer`

##### `sellToken` required

- **In:** `query`

Token being sold

`string`

##### `buyToken` required

- **In:** `query`

Token being bought (use 0xEeee…EEeE for native ETH where supported)

`string`

##### `sellAmount` required

- **In:** `query`

Positive sell amount in base units (base-10 string)

`string`

##### `allowWrapped`

- **In:** `query`

Opt in to wrapped (synthetic) settlement of the buy token; must match the signed intent. Default false.

`string`, possible values: `"true", "false"`

##### `smartWallet`

- **In:** `query`

Taker's delegated EIP-7702 smart-wallet implementation address; venues that can't verify its signatures are skipped

`string`

##### `sourceInclude`

- **In:** `query`

Comma-separated venues eligible to win `recommended`

`string`

##### `sourceExclude`

- **In:** `query`

Comma-separated venues excluded from winning `recommended`

`string`

##### `builderFeeBps`

- **In:** `query`

Per-request builder fee in human bps. Requires X-Api-Key. Must be ≤ the key's max builderFeeBps; omitted or 0 collects none. Paid to the key's builderFeeRecipient. Repeat the same value on /v1/submit. Combined with protocol bps, also capped by ARCUS\_MAX\_TOTAL\_FEE\_BPS.

`number`

##### `taker` required

- **In:** `query`

Wallet that will sign the settlement payload

`string`

##### `slippageBps`

- **In:** `query`

Max slippage in basis points (0–10000)

`integer`

### Relay a gasless spot → perp deposit

- **Method:** `POST`
- **Path:** `/v1/deposit`
- **Tags:** Deposits

Relays an EIP-712 signed deposit into SignedDepositProxy with relayer-paid gas. The router rebuilds the Permit2 typed data from the request fields, so every parameter is covered by the signature check; Permit2 re-verifies on-chain. Include the optional ERC-2612 `permit` for fully gasless first-time deposits.

#### Request Body

##### Content-Type: application/json

- **`accountIndex` (required)**

  `integer` — uint16 perp account index

- **`amount` (required)**

  `string` — uint256 as a base-10 string (token base units)

- **`anyoneCanExecuteCancel` (required)**

  `boolean` — Bound into the signed witness

- **`deadline` (required)**

  `string` — Unix seconds; the signature is void after this

- **`destination` (required)**

  `object` — "paxosDepositProxy" (1) for USDG; "bridgeVault" (0) for stock tokens

- **`owner` (required)**

  `string` — Signer / token owner; the deposit is credited to this address

- **`permitNonce` (required)**

  `string` — Random Permit2 nonce from the signed envelope

- **`signature` (required)**

  `string` — 65-byte (or EIP-2098 64-byte) EIP-712 signature over the Permit2 PermitWitnessTransferFrom with SignedDepositWitness

- **`token` (required)**

  `string` — Token to deposit

- **`chainId`**

  `integer` — Must match the router chain when present

- **`permit`**

  `object` — Optional ERC-2612 permit granting Permit2 an allowance, relayed on-chain right before the deposit so first-time depositors need no gas

  - **`deadline` (required)**

    `string` — uint256 as a base-10 string (token base units)

  - **`signature` (required)**

    `string` — 65-byte signature over the token's own ERC-2612 Permit

  - **`value` (required)**

    `string` — Must cover \`amount\`; sign max-uint for a one-time permit

**Example:**

```json
{
  "chainId": -9007199254740991,
  "owner": "0xf64780eAE9CFe162EF38f5224459a014a1007cd5",

  "amount": "10000000",
  "destination": "bridgeVault",
  "anyoneCanExecuteCancel": true,
  "permitNonce": "10000000",
  "deadline": "10000000",
```
