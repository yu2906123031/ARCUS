日期：2026-10-07

本轮覆盖 arcus_mm 做市主路径，以及根目录现货、永续与运维模块的现有测试。代码审查重点为行情、订单状态、账户核对、撤单、成交统计、报告和恢复边界。

## 找到并修复的问题

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| reconcile 后仍使用旧本地权益 | 迟到成交改变账本后，现有挂单可能按旧资金帽继续保留 | 核对后重新计算账本权益，再与交易所权益取小值；测试证明超预算挂单进入清理 |
| 终态订单被迟到无序号 OPEN 覆盖 | 已确认成交或撤销的订单重新变成非终态，清理可能误判或超时 | 拒绝终态向非终态回退，记录 order_state_ignored |
| clientId 对应订单 ID 被不同回报覆盖 | 已证明身份的订单可能被错误替换，破坏后续查询与撤单证据 | 非空原 orderId 必须一致，否则设置 fatal 并保持原身份 |
| 校时吞掉读取 429 | 连续采样继续撞限流，把限流混成无有效校时 | 429 立即结束本次采样并保留冷却；刷新进入暂停等待，不直接归类为时钟漂移 |
| 订单确认忽略读取冷却 | 确认路径收到 429 后仍在半秒后重读 | 下一次轮询时间不早于 API 冷却；期间仍接受 WS 终态，确认期限到达仍安全停止 |
| 其他 markout 期限挤掉 5 秒样本 | 成交密集时毒性统计突然清空，导致应有的溢价失效 | 每侧独立保留最多 2000 个已完成的 5 秒样本；1000 笔压力回归保留全部样本 |
| 坏日志事件与负采样延迟未校验 | 报告可能 TypeError 崩溃或接纳无效质量数据 | 非字符串事件和负延迟计入坏记录，不参与统计 |

这些问题均有新增回归用例；先复现失败，再修复通过。实盘杠杆仍为 **5 倍**，资金帽与订单、仓位、止损比例保持原配置。
